01 / PLATAFORMA

Uma bancada de engenharia,
não uma caixa-preta.

BinLab está evoluindo de uma ferramenta Python de terminal e desktop para uma plataforma local-first. Cada camada tem responsabilidade definida; cada recurso deve ser verificável, testável e documentado.

⌘

04 / SEGURANÇA

Seguro por desenho.
Verificável na prática.

Segurança não é um módulo isolado. É uma propriedade da arquitetura, das fronteiras de entrada e dos processos que executam ferramentas locais.

Ler o modelo de ameaças ↗
01
Inspeção estática

Artefatos importados não são executados nem compilados automaticamente.

02
Limites de recursos

Leitura, parsing, memória e subprocessos possuem limites documentados.

03
Serviço local protegido

Loopback, origem explícita, autenticação, CSRF e DNS rebinding serão tratados antes da API.

04
Auditoria contínua

Testes de abuso, fuzzing e revisão complementar fazem parte dos critérios de liberação.

!

Estado atual: a inspeção de artefatos via API permanece bloqueada pela Issue #2 até a conclusão de fuzz/property tests, testes de fronteira e revisão de segurança.
